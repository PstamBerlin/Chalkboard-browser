The Book of
Chalkboard

Every version, every change, and why it happened.

1.1 (coming soon) · run on exactly one computer

Chalkboard is a web browser with no AI, no telemetry, easy extensions and too many settings. It was written by an eleven year old working mostly from a phone, and it now runs on a real Mac.

The versions below were not planned. They are what the work turned out to be, grouped after the fact and named here for the first time, because a project that called itself beta 0.5 for weeks deserves a better memory of itself than that.

One rule was followed the whole way, and it explains most of the decisions that follow.

If you cannot replicate it, there is not enough customization. Peter, about browser themes

He said it about themes. It ended up driving the deepest parts of the design, including two tokens that exist only because something could not be copied exactly.

0.1

First Light

a window that loaded a page

An Electron shell that opened a window, loaded a page, and had tabs. Nothing here was clever. It mattered because it existed.

A real browser process with a real page inside it, not a mockup of one. The architecture choice made here shaped everything after it: pages live in their own view, entirely separate from the browser's own interface. That sounds like a technicality and is not. It is the reason websites can never touch Chalkboard's styling, and the reason Custom CSS is safe.

Decisions that stuck

  • No AI anywhere, deliberately, forever.
  • No telemetry. Not switched off, never written.
  • The browser's own interface is a web page, so it can be restyled by the same rules as anything else.
0.2

The Tray

every value becomes a token

The Chalk Tray, and the idea that made the product.

Every visual value in the browser became a named token. --stroke for the outline colour, --radius for corners, --glow for the halo, and dozens more. The tray does nothing clever. It rewrites tokens. That is the whole engine.

The consequence is the important part. Adding a new setting does not mean writing new code that draws something differently. It means adding one control that names a token. It wires itself up.

Also in this version

  • The chalk:// new tab page, served with your own colours already in it.
  • Remappable shortcuts: sixteen commands, one combo each, and giving a combo away visibly takes it off whatever had it.
  • Custom CSS, applied as you type, over the browser's own styles.
  • Tracker blocking, cross-site cookie stripping, encrypted DNS, and permissions that ask every time.
  • The disguise: Chalkboard reports itself as ordinary Chrome, because a browser nobody else uses is a perfect fingerprint.
0.3

Boards

looks you can save and send

Looks became objects.

A Board is every token as one line of text. Copy it, send it to a friend, and they get your exact browser. Six shipped:

Ember Ice Chalk Acid Grape Paper

This is where the project stopped being a browser with a settings panel and became a browser about settings.

The naming held too: Chalkboard, chalk on a board, everything drawn as outlines instead of filled blocks. The Chalk Tray. The chalk page.

0.4

Paper

a website, a guide, real apps

Everything around the browser.

  • The website, one self-contained HTML file with the browser's source and the guide embedded inside it as data. No hosting, no server, works offline. Peter later built Fry City OS the same way without being told to, which is a good sign for an architecture.
  • The guide, eight pages, every illustration drawn as vector graphics from the same tokens the browser uses. Not screenshots. The browser had never been run, so there was nothing to photograph.
  • Real Mac apps, Apple Silicon and Intel, built through a packaging tool that kept dying halfway. Solved by building to a folder and zipping it by hand, which turned out faster and cannot half-write a file.
  • Phone-friendly CI, so the whole thing can be built from a phone, which is how most of this project was made.
0.5

The Long Beta

split view, browser looks, modes, fonts

The version that lasted weeks and grew the most. It is really five projects wearing one number.

Tabs grew up

Split view, where the gap between the two pages is the window background so it is automatically in your board's colour. Pinned tabs, small and first. Drag to reorder. A right-click menu with duplicate, mute, close others. And crash-proof sessions: tabs are snapshotted every thirty seconds, so a force quit costs half a minute instead of everything.

Board files

Chalkboard grew its own file format. A .board file is your whole look, saved from the tray, opened by double click. Registered with macOS, and read from the command line on Windows and Linux, because those hand a double-clicked file over as an argument instead of an event.

This became the best idea in the project. The site, the app, and anyone you send a file to all speak the same language.

The borrowed looks

Nine boards in the colours and shapes of browsers people already use. The pitch: switching does not have to look like switching.

Fox Shiny Cupertino Edgy Lion Gamer Onion Curve Ninety Five

These were rebuilt three times, each time because Peter checked them against the real browsers on his phone and found them wrong.

  1. First they were Chalkboard's outline style wearing other brands' colours. Wrong, because real browsers are flat.
  2. Then flat, but with the brand colour in the outlines. Still wrong: real browsers keep their colour in the logo, not the interface. Firefox's interface has no orange in it at all. So the accent moved to the icons, where those browsers actually keep it.
  3. Then Chrome's colours turned out to be reversed, and could not be fixed. Chalkboard had one background token painting both the tab row and the toolbar, and Chrome needs them different.

What the rule did here

A new token was added, --strip, giving the tab row its own colour. Firefox, Tor, Edge and Brave turned out to layer their rows the same way and got the same fix. The inability to replicate something was treated as a missing feature rather than an acceptable difference.

Three modes

First Beginner and Expert. The verdict from the person it was built for: Beginner was too bare, it needed a bit of customization too. So it became Easy, Medium, Expert: the first minute, the fun knobs, and every knob there is. Nothing is ever removed, deeper controls just wait for the tier that asks for them.

Fonts

Boards were changing every visual value except the typeface, which meant Ninety Five was only half a costume. Every board now carries a font: Acid is monospace, Paper is serif, Ninety Five is Tahoma, Edge and Opera GX use Segoe, Chrome prefers Roboto.

The gallery

The website grew a downloadable board gallery, ending at twenty seven packs: fifteen that ship inside the browser and twelve that exist only on the site, including Blackboard, Vapor, Comic, Typewriter, Frost and Slate.

Slate exists because of a question: why does there always have to be a coloured line? There did not. Thickness zero plus glow zero gives solid blocks. That same question unlocked the flat browser looks, which had been impossible until borders could be zero.

The fact-check

Three full audits, every claim on the site and in the guide checked against the code. Sixteen corrections. The site had been claiming there was no list of themes to pick from, directly above a list of themes to pick from. The guide's toolbar drawing was missing its bookmark star. The Android notes still advertised six privacy features that had quietly become manual settings.

Fifteen of those were words corrected to match the code. One was the opposite: the claim that board files open by double click was only true on macOS, so the code was changed to make the claim true.

0.6

Field Report

it runs, and the truth arrives

The version where Chalkboard was run for the first time.

Every line up to this point had been written blind. No screenshot of the browser existed anywhere. Then it was opened on a real computer, and the report came back.

works the most important word in the project

Everything in this version came from that.

  • A loading bar, requested within minutes of first launch. A thin line of the board's accent at the seam between toolbar and page, moving on the engine's three real milestones rather than a made-up percentage. Chalk pages show no bar, because pretending to load a local page would be theatre.
  • Website CSS, dad's idea and a good one: your own styles injected into websites themselves, for every site or just one, applied as you type. Chrome CSS themes the browser; this themes the web.
  • The wallpaper fix. The page image had never worked, and it was broken in three places at once: the renderer stripped it before sending, the main process rejected it as a security risk, and nothing anywhere painted it.
  • Version sync, so the number lives in one file and reaches the app, the site, the guide and the notes from there. Settings and website can no longer disagree.

Found later, in this version's own new code

A crash risk in the updater, stale stylesheet keys after navigation, a memory leak in the loading bar's tab map, a missing size limit on wallpapers, and two elements on the website sharing one id. New code is always the least examined code.

0.7

Self Service

it updates itself and wears its skin

The browser learned to look after itself.

  • Update from a file. The tray takes a small zip of the browser and swaps it in, then restarts. About fifty kilobytes, because the engine underneath never changes between versions. Going back is one button. Nothing is downloaded on its own and nothing is checked online. This exists because downloading ninety-eight megabytes twice, and having it arrive incomplete twice, is a bad way to spend an afternoon.
  • Textures. Sixteen grains over the browser's own surfaces: chalk, chalk dust, paper, concrete, static, film, frost, linen, carbon, corduroy, crosshatch, canvas, graph, dots, halftone. All generated from four maths functions, none fetched, and websites are never touched.
  • Textures on boards, but only where the material is the idea. Chalk wears chalk grain, Paper wears paper, Acid wears film static, Gamer wears carbon, Ninety Five wears a halftone dot screen. Every other board says none explicitly, so the nine browser looks stay clean and switching stays predictable.
  • A living mark. The new tab page shows the Chalkboard window drawn from your live tokens. Not a picture of the logo: the logo made of your settings.
  • A living app icon. On macOS the dock icon is repainted from those same tokens whenever the look changes. Switch to Grape and the icon goes violet. Any board anyone invents gets an icon nobody drew.
1.1

Aurora

a new look, and the old one kept · coming soon

The first version with a new face, and the first one that promised to keep the old face exactly as it was.

The look started in another of Peter's apps, a photo editor: a violet mesh, dark at the top and bright at the bottom, frosted glass, one butter yellow accent. When it moved into the browser, Peter named it Aurora. It became the default, with a light version for daytime, and a Device setting that follows the computer from one to the other.

Aurora Sunrise Bloom Lagoon Meadow Dusk Smoke

Borrowed from Firefox, done Chalkboard's way

Firefox 157 had just redesigned itself, and the good parts came over. The tab you are on became a pill: a dark fill, and a thin edge running from violet to pink. Window density, from Compact to Touch. Tabs on the side. A list of all your tabs you can search. Six gradient boards came too, under our own names: Sunrise, Bloom, Lagoon, Meadow, Dusk and Smoke, each with a light and a dark half.

The rule underneath did not change: nothing is fetched. Aurora's two fonts, Unbounded and Manrope, ship inside the app. The new tab page got a world clock, a focus timer and lists, all kept on your own machine, and no weather, news or stocks, because those would mean the page talking to someone. The shortcuts start empty apart from one + tile. Chalkboard never guesses your sites.

The old look, kept exactly

Ember, the 1.0 default, is called Classic now, and it is the exact 1.0 look: no glass, no mesh, the outline tab, the 1.0 fonts. It is one click away, in the tray and on the new tab page. All fifteen 1.0 boards stayed, unchanged.

What the rule did here

A new look could have been one switch, Aurora or Classic. That would have failed the rule, because nothing in between could be built. So every part of the new look became its own token: --mesh for the background, --frost-blur for the glass, --grain, --tabstyle for the tab, --tab-edge-a and --tab-edge-b for the pill's edge, and --display for the title font. They sit together in a Style group in the tray. A board sets them all; change one and the rest stay. You can rebuild the old look by hand, or wear Classic's colours with Aurora's tab.

The bug in 1.0

While the tray was starting up, it saved its own default values over your board, before it had read your board. So in 1.0 the look never survived a restart: every launch came back as Ember.

1.1 fixes it. Because every 1.0 install has that accidental default saved, 1.1 switches each one to Aurora once. After that, what you pick stays picked.

Then Peter asked for more: settings you save are always saved. Every setting, in the tray and on the new tab page, now survives a normal quit, a crash right after the change, an update from a file, and clearing your browsing data. Clearing wipes cookies, site data and the cache. It never touches your settings.

The things that keep being true

Honesty in previews

A card advertising a board must obey that board's own values. This started as a small fix and became a rule: colour, corner shape, border width, glow strength, texture and font all flow from the same values as the file being handed out. Nothing in a preview is decorative.

Nothing is forced

The coloured outline was Chalkboard's signature, and it could always be removed entirely. In 1.1 the default traded it for glass, and Classic keeps it one click away. The AI-free stance is not a limitation to work around, it is the product.

Say the limit out loud

The page wallpaper cannot show behind websites, because websites paint their own backgrounds, so the control says so. Copy protection means Netflix will not play, so the site says so. Android is written but unfinished, so every Android button says coming soon.

Who found what

Worth recording honestly. The automated checks in this project verify that code matches code: every element exists, every bridge is wired, every channel is handled, nothing is registered twice. Those checks caught real bugs, including one that would have crashed the app at launch.

They never caught a single one of these:

  • The glow that had stopped being proportional, so Acid did not look neon
  • The themes that did not turn blocky when they should
  • Chrome's reversed colours
  • Firefox on a phone being bluer than on a desktop
  • The site claiming there was no list of themes, above a list of themes
  • The page wallpaper doing nothing at all

All six were found by looking at the thing. That is the argument for running software instead of only reading it.

The file formats

  • .board — a small file containing every token: colours, shapes, glow, speed, font, texture, tab strip, and since 1.1 the background, the glass, the grain and the tab style. Double-click to open. This is how looks travel between people.
  • The update zip — the browser's own source, about fifty kilobytes, applied from inside the tray.
  • The site — one HTML file with the source and the guide embedded as data. No hosting required. Build number in the footer, because a folder full of identically named downloads is its own kind of bug.

Long live the cook.
